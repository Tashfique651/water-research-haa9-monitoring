# Post-protocol exact-capacity sensitivity

Added on 19 September 2026 after inspecting the training-calibrated forward results, at the integration review's request. This is an explicitly post-protocol sensitivity, not a prespecified confirmation. The primary frozen workload-threshold analysis remains unchanged and all its results are retained.

For each of the same five declared capacity fractions (0.05, 0.10, 0.15, 0.20, 0.30), within each outer evaluation fold allocate exactly floor(fraction times number of evaluation PWS) follow-up slots to the highest out-of-fold scores. Use a deterministic SHA256 PWS hash as the common tie-breaker; outcome labels never enter allocation. Apply the same slot count separately to each scalar and logistic score. This compares a batch allocation policy that can rank the current pool, not a fixed threshold applied independently to one future system. Its achieved capacity is slightly below the nominal fraction due to integer rounding but exactly equal across comparators.

Report the complete operating-point family and paired HAA9-minus-HAA5 sensitivity differences, with a simultaneous centered-bootstrap band across all five capacities for each comparator pair. Use the same 5,000 whole-PWS resamples and seed as the primary analysis. Fits, scores, rankings, and allocated slots remain fixed during uncertainty calculations. Thus bootstrap uncertainty is conditional on the observed allocation and does not include model retraining or a new allocation optimization in each resample. Do not choose a preferred capacity based on these results.
